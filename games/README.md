# Копилка игр LimeDrive

Каждая игра — папка в `games/`. Игра попадает в копилку только с метаданными:
без них это не шедевр в коллекции, а потерянный файл.

## Структура

```
games/
  my-game/
    game.json        # сама игра (формат из PROMPT.md)
    meta.json        # паспорт игры (обязательно)
```

## Шаблон meta.json

```json
{
  "title": "Название игры",
  "author": "Имя автора",
  "date": "2026-08-24",
  "engineVersion": "1.0.0",
  "origin": {
    "method": "generator|manual|hybrid",
    "prompts": [
      { "text": "исходный промпт", "iteration": 1 }
    ],
    "manualEdits": ["описание ручных правок, если были"]
  },
  "fixation": {
    "sha256": "хеш канонизированного game.json",
    "fixedAt": "2026-08-24T12:00:00Z",
    "evmRegistration": { "filed": false, "certNumber": null }
  },
  "rights": "творческий вклад принадлежит автору; совпадения генераций не нарушение"
}
```

Зачем каждое поле:

- `origin.prompts` и `manualEdits` — **доказательство творческого вклада**
  (без него охраны нет вообще, см. docs/legal/01);
- `fixation.sha256` + `fixedAt` — приоритет в реестре при совпадении генераций
  (см. docs/legal/04);
- `evmRegistration` — если игра регистрируется как программа для ЭВМ
  (см. docs/legal/03).

## Правила пополнения копилки

1. Одна игра = одна папка = один `meta.json`.
2. Хеш считается по канонизированному JSON (сортировка ключей) — иначе
   сравнение с чужими фиксациями не сработает.
3. Промпты сохраняются как есть, до правок — история ценнее «причёсанной» версии.
4. При публикации игры вне проекта — атрибутация «Создано на движке LimeDrive».
5. Совпавшая у другого игрока генерация — не повод для конфликта: приоритет
   решает дата хеша, а не эмоции.
