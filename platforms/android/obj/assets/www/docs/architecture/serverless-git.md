# Serverless-архитектура LimeDrive: «живём в гит-клоне»

Принципы владельца проекта, положенные в основу:

1. **Серверов своих не ставим** — вообще.
2. **Клиент живёт в клоне git**: движок, игры, реестр фиксаций — файлы репозитория.
3. **Пользовательские данные не храним по возможности**: всё состояние игрока
   остаётся на его устройстве; наружу уходят только хеши и псевдонимы.
4. Хостинг — то, что даёт git-платформа бесплатно («гитовый ранер»).
5. Транспорт между игроками — что угодно, что умеет переносить файлы/патчи,
   включая почту.

## Как это ложится на уже построенное

| Компонент | Serverless-реализация | Статус |
|---|---|---|
| Реестр приоритета | `registry/fixations.jsonl` — append-only цепочка с печатями; **коммит в git подтверждает приоритет** датой | Работает (`tools/registry-export.js`) |
| Арбитр споров | CI-раннер: workflow проверяет целостность цепочки на каждый PR — подделку отклоняет машина, а не суд | `.github/workflows/validate-registry.yml` |
| Каталог игр | Статика `games/**` + GitHub/GitLab/Cloudflare Pages из ветки | Файлы готовы, включить Pages |
| Движок и плеер | Те же статические файлы | Работает |
| Копилка meta.json | Файл в клоне рядом с игрой | Работает |

## Каналы синхронизации реестра

1. **PR в центральное зеркало** (GitHub/GitLab): игрок делает
   `node tools/registry-export.js add …` → commit → push → PR.
   CI автоматически проверяет печати; merge = глобальное признание приоритета.
2. **Почта**: `git format-patch` + вложение письмом, либо `git bundle`
   файлом — получатель применяет и включает в свою цепочку. Полностью офлайн.
3. **LAN / знакомые**: `git daemon` или обмен через Syncthing-папку клона.
4. **Слияние двух клонов**: `mergeRecordLists()` дедуплицирует и пересобирает
   цепочку детерминированно — расхождения не страшны.

## Android-«демоны под капотом»

Задумка «пусть андроид сам таскает клон» реализуема без root:

- **Termux**: полноценный git; `sshd`/`git daemon` — устройство раздаёт клон
  по локальной сети; `crond` — периодический `git pull && registry sync`.
- **Syncthing for Android**: папка клона синхронизируется между устройствами
  напрямую, без облака.
- PWA уже стоит «на главный экран»; связка PWA (игра) + Termux (синхронизация)
  закрывает сценарий без единого сервера.

## Честные границы

- Центральный git-хост остаётся точкой сборки — но это чужой бесплатный сервис,
  данные публичны и обезличены (хеш + псевдоним + дата), приватность не страдает.
- Дата в `fixedAt` задаётся клиентом; при споре приоритет подтверждают датой
  коммита git-хоста, поэтому важно коммитить promptly.
- Письма/bundles не дают мгновенности — это транспорт «для упорных».

## Инструменты (уже в репо)

```
node tools/registry-export.js verify [file]          # целостность цепочки
node tools/registry-export.js add <game.json> …      # зафиксировать игру
node tools/registry-export.js import-browser <dump>  # влить дамп из localStorage
```

CI: `.github/workflows/validate-registry.yml` — гоняет `verify` на каждый PR
в `registry/**`.

Связанное: `docs/legal/04-collision-resolution.md` (правила приоритета),
`docs/patent-service-concept.md` (API), `generator/generator.html` (кнопки
⚖ Fix / To collection пишут в тот же формат).
